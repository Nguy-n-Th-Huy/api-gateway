# Tasks: add multi-group API keys

Read `design.md` before starting: it fixes the storage mapping (D1), the single backend gate (D2), the list of relay-path behaviour that is already correct and must NOT be touched (D3), the new form model (D4), the picker/toggle split (D5), the table rendering (D6) and the translation rules (D7).

**Standing constraints for every task**

- No schema change and no migration: `tokens.group` / `tokens.auto_groups` / `tokens.cross_group_retry` keep their meaning. Do not add a column, an index or a migration file.
- No `encoding/json` in business code: JSON goes through `common.Marshal` / `common.Unmarshal*`.
- `relaykit/` must not be touched, so `cd relaykit && GOWORK=off go build ./...` is NOT part of the proof for this change.
- Do not touch `new-api` / `QuantumNous` branding.
- Files outside this change's blast radius (`middleware/auth.go`, `model/token.go`, `web/src/features/keys/**`, `web/src/i18n/locales/en.json`, `web/src/i18n/locales/vi.json`) must stay untouched.

**Proof commands (run from the repository root; group 7 executes them)**

- Go: `go test ./middleware/... ./controller/... ./service/...`, `go vet ./middleware/...`, `gofmt -l middleware/auth.go model/token.go`
- Frontend (the repo uses bun with `web/bun.lock`): `bun run --cwd web typecheck`, `bun run --cwd web lint`, `bun run --cwd web test`, `bun run --cwd web format:check`
  - targeted test run: `bun run --cwd web test src/features/keys`
- No database verification matrix is required: no column, index or migration is added.
